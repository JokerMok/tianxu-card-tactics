# 横屏战术卡牌原型系统模块拆分清单

版本：v0.1  
日期：2026-06-30  
状态：历史模块稿，由《PVE 全系统模块矩阵》替代

## 1. 拆分原则

- 先验证战斗，再接成长。
- 先做本地闭环，再接账号和服务端。
- 商城、抽卡、支付在战斗和成长验证后接入。
- 所有系统必须配置化，不能写死在逻辑代码中。

## 2. 优先级定义

| 优先级 | 含义 |

| P0 | Prototype 必须完成 |
| P1 | Vertical Slice 必须完成 |
| P2 | Alpha 必须完成 |
| P3 | Soft Launch 前完成 |
| P4 | 上线后扩展 |

## 4. 版本拆分

### 4.1 Prototype

必须完成：

- M001 战斗核心。
- M002 战斗表现。
- M003 敌方 AI。
- M004 卡牌系统。
- M005 牌组系统。
- M006 关卡系统。
- M007 配置系统。
- M008 战斗日志。
- M010 本地存档。

目标结果：

- 本地可玩。
- 有 20 张卡。
- 有 10 个关卡。
- 可导出战斗日志。

### 4.2 Vertical Slice

必须完成：

- M009 新手引导。
- M011 章节地图。
- M012 奖励系统。
- M013 货币系统。
- M014 背包系统。
- M015 卡牌升级。
- M016 任务系统。
- M017 玩家等级。

目标结果：

- 玩家可从进入游戏到完成第一章。
- 可获得奖励并升级卡牌。
- 可编辑牌组继续推进。

### 4.3 Alpha

必须完成：

- M018 账号系统。
- M019 云存档。
- M020 英雄系统。
- M021 装备系统。
- M022 天赋系统。
- M023 体力系统。
- M024 抽卡系统。
- M025 商城系统。
- M026 模拟支付。

目标结果：

- 成长、经济、商城和抽卡形成闭环。
- 仍不接真实付费。

### 4.4 Soft Launch

必须完成：

- M027 活动系统。
- M028 邮件系统。
- M029 公告系统。
- M030 正式支付。
- M031 订单系统。
- M032 埋点系统。
- M033 运营后台。
- M034 客服工具。
- M035 风险校验。
- M036 隐私合规。

目标结果：

- 可小规模上线验证留存、付费和内容消耗。

## 5. 不进入首发的模块

| 模块 | 原因 |
|---|---|
| PVP | 平衡和反作弊成本高，会干扰 PVE 验证 |
| 公会 | 需要社交、活动和运营支撑，首发价值不高 |
| 交易 | 容易破坏经济和抽卡价值 |
| 拍卖 | 服务端和监管成本高 |
| 玩家自制关卡 | 内容审核和难度控制复杂 |
| 实时联机协作 | 网络同步成本高 |

## 6. 模块验收总线

每个模块验收必须包含：

- 入口。
- 状态。
- 配置。
- 变更记录。
- 异常处理。
- 数据埋点。
- 关闭或降级方案。

商业化模块额外必须包含：

- 订单或流水。
- 限购校验。
- 重复领取保护。
- 配置下架能力。
- 客服查询能力。

## 7. 当前排期建议

第一轮只做 Prototype。  
Prototype 达不到以下标准，不进入 Vertical Slice：

- 单局 5 至 8 分钟。
- 玩家每回合至少 1 个有效选择。
- 三条路线都有压力。
- 10 个关卡中至少 8 个能正常完成。
- 战斗日志能定位失败原因。
