版本：v1.1  
日期：2026-07-12  
状态：历史验证文档；正式实现路线已迁移至 Cocos Creator 3.8 LTS

## 1. 技术范围

本文件记录 React、TypeScript 和 Vite 网页原型的验证实现。其战斗规则、配置字段、状态转换和测试结果可以作为迁移依据，但 React 表现层不再作为正式版本技术路线。正式版本采用 Cocos Creator 3.8 LTS、2D 横版双战线战场、Web Desktop 首发与 Android 共用工程。

## 3. 分层

| 层 | 职责 | 禁止事项 |
|---|---|---|
| data | 静态配置和文本 | 不包含状态修改逻辑 |
| battle | 状态机、规则、随机和敌方决策 | 不访问 DOM 或 React |
| selectors | 计算合法目标和展示数据 | 不修改状态 |
| components | 展示单个战斗对象和输入 | 不直接改写 BattleState |
| layouts | 组织信息层级 | 不复制战斗逻辑 |
| App | 行动窗口延迟、用户动作和布局切换 | 不实现卡牌专用规则 |

## 4. 状态更新

- 所有战斗动作通过 `dispatchBattleAction(state, action)` 返回新状态。
- 核心动作包括 `BEGIN_TURN`、`PLAY_CARD`、`END_TURN` 和 `RUN_ENEMY_TURN`。
- 用户动作包括 `SELECT_CARD`、`SELECT_LANE`、`SELECT_UNIT`、`PLAY_CARD`、`CANCEL_SELECTION`、`END_TURN`、`TOGGLE_AUTO_END`、`SET_SPEED` 和 `RESTART`。
- 规则函数不得读取系统时间或 `Math.random()`。
- 随机结果只能通过带游标的确定性随机数生成器获取。
- 动画状态不进入战斗规则状态。

## 5. 行动窗口与时间

- 玩家行动窗口不使用持续推进计时器。
- 自动托管每次只发出一个合法动作；单位部署、技能决策和 `END_TURN` 均通过既有状态机执行，不直接修改实体。
- 敌方行动通过一次延迟调用 `RUN_ENEMY_TURN`，规则结算保持同步和确定性。
- 倍速只改变玩家托管与敌方表现延迟，不改变状态转换内容。
- 页面不可见、竖屏或视口不足时不执行玩家托管和敌方行动表现。
- 切回页面后不得补算离线行动窗口。

## 6. 渲染

- 1v1 战场使用 CSS Grid 渲染两行十二列；召唤区域为双方靠近英雄的三列。
- 单位使用绝对定位于对应格子内，不使用 Canvas，便于触控、焦点和无障碍验证。
- 动画仅使用 `transform` 和 `opacity`。
- 网格尺寸由容器计算，不因单位和状态内容变化。
- 三种布局复用同一状态实例和组件，不重新初始化引擎。

## 7. 错误边界

- 配置启动前执行引用、范围、牌数和枚举校验。
- 非法动作由引擎返回原状态并追加拒绝事件。
- 规则异常暂停战斗并显示可重开状态。
- 胜负结束后忽略所有推进和出牌动作。

## 8. 测试

| 类型 | 范围 |
|---|---|
| 单元测试 | 准备值、部署、移动、索敌、伤害、死亡、技能和胜负 |
| 确定性测试 | 相同种子与动作序列结果一致 |
| 配置测试 | 三十张牌、引用、范围和枚举合法 |
| 组件测试 | 卡牌禁用、目标高亮、控制按钮和布局切换 |
| 浏览器测试 | 完整开局、连续出牌、结束回合、托管开启与接管、倍速、胜负、重开 |
| 视觉测试 | 四个目标视口无重叠、无横向滚动和无空白战场 |

## 9. 运行命令

```bash
npm run build
```

## 10. R1 后迁移

R1 验证通过后，保留战斗规则、配置结构和测试；三种布局只保留评审选定方案。后续 Cocos Creator 实现应以相同配置字段和事件语义重写，不直接复用 React 网页表现代码。
