## 1. 迁移结论

美术方向、角色设计、卡牌立绘、丝袜差异化、Cos 结构和商业宣传规则继续生效。战场单位、环境和特效已从预渲染 2D 资产链迁移为 Cocos Creator 3.8 LTS 实时 3D 资产链。Web 首发只保证 PC 浏览器，Android 复用工程和源资产，通过平台画质配置降级。

本次迁移通过。A0 开始前仍需完成正交相机实机锁定，不允许直接进入二十八兵种批量建模。

## 4. 对抗式复核

### 4.1 性能预算是否过度保守

PC 浏览器首发允许比手机 Web 使用更高模型和贴图预算，但浏览器仍受显存、下载和 JavaScript 主线程影响。现行预算保留 Draw Call、透明层、同屏骨骼和资源分包限制，没有按桌面客户端规格放宽，结论合理。

### 4.2 是否应给全部单位制作 LOD

固定正交相机下普通单位屏幕尺寸变化有限，批量制作 LOD 的成本高于收益。现行规范只要求首领、行营展示和近景模型按测试增加 LOD，避免无效生产。

### 4.3 立绘尺度能否直接转为战场模型

不能。卡面中的薄纱、长摆、高开衩、细丝袜纹样和悬浮饰件在实时 3D 中会产生透明排序、穿插和轮廓噪声。现行规范保留角色身份与色彩，同时要求完整战斗内层、贴图化细节和收束背饰，未改变角色核心设计。

### 4.4 Web 与 Android 是否真正共用资产

共用源模型、骨架、动画、Prefab 和依赖关系；运行时贴图压缩、阴影、粒子数量和材质质量分别构建。现行规范未把“共用工程”误写为“完全相同的构建产物”。

## 5. A0 前置条件

1. 使用灰盒场景测试 40°、45°、50° 三档俯角。
2. 锁定 `1920×1080` 下普通单位投影高度。
3. 完成 U002、U008 和 E104 的真实 3D 资产链。
4. 以 24 个单位同时运行验证骨骼动画、透明材质、阴影和特效预算。
5. 在 Chrome 与 Edge 完成完整一局战斗。

未完成以上条件时，不允许量产全兵种模型、全章节场景和大批量技能特效。
