## 一、评审结论

现有二十八张单位卡面通过原型阶段验收，可用于网页体验版和 Cocos 2D 原型。十张核心角色图已完成唯一候选归档，但尚未通过正式卡面验收。2D 战场单位、六层战场、战斗 UI 和特效尚未形成可运行资产，A0 美术技术验证未完成。

项目正式路线调整为 Cocos Creator 3.8 LTS、2D 横版双战线战场、Web Desktop 首发与 Android 共用工程。人形单位使用 2D 骨骼动画，异兽与机关按复杂度采用骨骼或人工校正序列帧，场景使用六层视差。实时 3D 模型、PBR 材质和三维场景不再作为战斗资产要求。

### 3.2 核心角色

十名角色已经按 C001-C010 建立唯一候选目录。C002 原图为 `862×1824`，运行时版本曾被直接拉伸，现已从原始长图按 2:3 安全区裁切为 `1024×1536`，重新导出两档 WebP；原图保存在 `_archive_pre_standardization`。

## 五、2D 路线准入条件

A0 只生产并验证以下四项，未通过前不批量制作其余战场资产：

1. U002 折锋枪兵：完整 2D 切片、关节补绘、骨骼、待机、移动、攻击、受击和退场动画。
2. U008 霆脊巨兽：骨骼与人工校正序列帧二选一对比，验证大体型遮挡和性能。
3. E104 双线交锋：天空、极远景、远景、中景、双线路面、前景与局部动态层组成的六层场景。
4. 战斗主界面：两条战线、部署区、五张手牌、准备值、托管、速度、英雄生命与状态反馈完整联调。

PC 浏览器同时显示二十四个单位时，必须验证纹理占用、Draw Call、透明排序、图集切换、动画更新和加载时间。Android 只在 PC Web A0 通过后执行降级配置验证。

## 六、处置决定

- 单位卡面：继续用于原型，不再重复重做已通过条目。
- 核心角色：保留身份候选，按 C001-C008 逐张重做正式卡面，明确丝袜颜色、织纹、袜口和服装衔接；C009-C010 保留男性候选并统一光照。
- 卡面母版：正式生产必须输出原生 `2048×3072` 或等效高细节分层源文件，禁止把 `1024×1536` 机械放大后标为母版。
- 战场资产：停止实时 3D 生产，转入 U002、U008、E104 和战斗 UI 的 2D A0 验证。
- 运行时资源：继续使用 `768×1152` 与 `256×384` 两档 WebP，任何非 2:3 源图必须先裁切，不得拉伸。

## 七、最终判定

卡面原型包：有条件通过。  
核心角色正式卡面：不通过。  
Cocos 2D 战场 A0：未完成。  
全量商业美术生产：暂不准入。
