# Cocos Creator 真 3D 美术技术规范

版本：v1.0  
日期：2026-07-14  
状态：生效  
适用范围：Web Desktop 首发版本、Android 共用工程  
依据：《核心战斗规则文档-v1.6》《美术风格与素材生产规范-v2.1》《网页体验版UX与视觉规范》

## 1. 技术路线

项目采用 Cocos Creator 3.8 LTS、真 3D 正交俯视战场、2D 屏幕界面。Web 版本只保证 PC 浏览器，Android 复用同一工程、源模型、动画、Prefab 与逻辑，通过平台配置降低贴图、阴影和特效等级。

战场单位、地面、阵地、建筑、部署标记和主要战斗特效均在三维空间中运行。卡牌立绘、头像、卡框、图标、章节地图、宣传图和大部分屏幕界面继续使用 2D 资产。

Web Desktop 以常规浏览器渲染能力为基线，不以 WebGPU、实时全局光照、体积云、高成本景深或多层透明材质作为必要效果。

## 2. 首发性能基线

| 项目 | R1 基线 |
|---|---|
| 浏览器 | 当前稳定版 Chrome、Edge；Firefox 完成兼容性检查 |
| 设计分辨率 | `1920×1080` |
| 最低可用分辨率 | `1280×720` |
| 画面比例 | 16:9 为基准，兼容 21:9；关键战斗区不得因宽屏增加可操作范围 |
| 帧率 | 目标 60 fps；高峰不得持续低于 45 fps |
| 同屏战斗单位 | 24 个普通单位、2 个统领或阵地主体、1 个大型首领 |
| 可见三角面 | 常态不高于 45 万，峰值不高于 60 万 |
| Draw Call | 常态不高于 120，峰值不高于 160 |
| 显存纹理占用 | 单场战斗解压后不高于 512 MB |
| 首屏资源 | 只包含启动界面、基础 UI、公共材质和首场必要资产 |

以上数值用于约束美术生产，不代替真机测量。A0 使用一台集成显卡 PC 和一台中端独显 PC 记录 GPU 时间、Draw Call、三角面、纹理占用与加载时间；任一指标超限时，先减少材质、透明层和特效覆盖，再降低模型精度。

## 3. 正交战场镜头

### 3.1 初始参数

- 使用 Orthographic Camera，初始俯角为相对水平面 45°。
- A0 同时测试 40°、45°、50° 三档，只允许改变俯角，不同时改变单位比例、光照或场景复杂度。
- 两条战线沿世界 X 轴推进，战线间隔沿世界 Z 轴展开，Y 轴只承担高度。
- 单位站立点、技能落点、部署格和生命条投影均以脚底枢轴为基准。
- 16:9 下完整显示双方阵地和十二格战线；21:9 只增加两端环境，不增加战斗信息。

### 3.2 可读性

- 普通人形单位在 `1920×1080` 下投影高度为 88-112 像素，大型单位为 128-180 像素。
- 战场模型保持 7.5-8 头身的成年比例，不使用大头、短肢或幼态比例。
- 武器、肩部、背饰、翼根、甲片和长摆可适度扩大，但不得破坏正常人体比例。
- 同类单位优先通过武器方向、上半身外轮廓和色块区分，不依赖面部细节、丝袜纹样或微小饰件。
- 敌我双方使用真实旋转和阵营材质参数，不制作左右镜像模型。

## 4. 战场单位资产

### 4.1 正式交付

每个单位交付以下资产：

| 资产 | 格式与要求 |
|---|---|
| 源模型 | Blender、Maya 或同等 DCC 源文件 |
| 交换文件 | FBX 2020 兼容格式或 glTF 2.0 |
| Cocos 资产 | Mesh、Skeleton、Material、Animation Clip、Prefab |
| 贴图 | Base Color、Normal、ORM；自发光仅在确有需要时增加 |
| 动画 | Idle、Move、Attack、Hit、Death；按职能增加 Cast、Heal、Stun 或特殊动作 |
| 预览 | 固定正交相机下的朝左、朝右、受击和技能可读性截图 |

### 4.2 模型预算

| 类型 | 三角面 | 骨骼 | 材质槽 | 运行时贴图 |
|---|---:|---:|---:|---|
| 普通人形单位 | 8,000-14,000 | 不高于 60 | 1，最多 2 | 1K |
| 具名战场角色 | 14,000-24,000 | 不高于 75 | 不高于 2 | 1K；必要时 2K |
| 普通异兽或机关 | 10,000-20,000 | 不高于 65 | 不高于 2 | 1K |
| 大型首领 | 25,000-45,000 | 不高于 90 | 不高于 3 | 2K |

- 单顶点骨骼权重不超过 4。
- 同族、同体型单位优先共用骨架、基础动作和材质模板。
- 固定正交战场中的普通单位不强制制作多级 LOD；首领、行营展示和近景角色按性能结果增加 LOD。
- 细小挂饰、发丝、丝袜织纹和刺绣优先烘焙进贴图，不建立独立几何体。
- 一张材质能够解决的色差使用材质参数或实例属性，不拆分新的材质槽。

### 4.3 动画

- 动画源文件统一为 30 fps，动作时间由战斗配置控制，不以动画长度反向决定规则时序。
- 移动动画必须支持原地循环，位移由逻辑节点控制。
- 攻击动作明确区分起手、命中和收招；命中事件由引擎事件绑定，不写死在模型文件中。
- 默认使用预烘焙骨骼动画。只有 IK、复杂混合或近景展示确有需要时，才启用实时骨骼计算。
- 披风、羽片和长发先使用骨骼摆动或手工动画；R1 不采用高成本布料模拟。

## 5. 服装与材质

### 5.1 统一材质层级

战场模型采用风格化 PBR。皮肤、漆器、金属、玉石、丝织物和异兽组织必须通过粗糙度、法线与色块区分，不依赖复杂屏幕特效。

| 材质 | 战场处理 |
|---|---|
| 皮肤 | 柔和高光，禁止塑料反射和大面积次表面模拟 |
| 丝袜 | 使用不透明贴图模拟透肤、织纹、后缝和光泽，不叠加真实透明皮肤层 |
| 薄纱 | 优先 Alpha Clip、抖动透明或单层透明壳 |
| 漆器 | 高光边缘明确，避免整片镜面反射 |
| 玉石 | 以颜色、粗糙度和局部自发光表现，不使用实时折射 |
| 金属 | 使用统一金属材质模板，减少独立材质实例 |
| 羽毛与毛发 | 使用卡片面或简化几何，透明层数受控 |

### 5.2 透明边界

- 卡牌立绘中的半透明丝袜和薄纱可以保留。
- 战场模型不得连续叠加皮肤、丝袜、薄纱三层透明面。
- 成人特殊版进入战场时必须使用完整遮蔽的战斗材质，不显示乳头、乳晕、下体、臀沟或私密轮廓。
- 年轻角色继续执行《角色年龄分级与表现规范-v1.0》，不得因三维材质增加透视、贴体或身体聚焦。
- 透明材质不得承担职业识别、敌我识别或五行识别。

## 6. 环境资产

### 6.1 结构

每个战场由以下部分组成：

1. 战斗地面与两条战线路面。
2. 双方阵地、部署区和首领占位区。
3. 关卡地标与剧情装置。
4. 低矮边界、掩体和非交互装饰。
5. 远景背景板、天空和环境粒子。

环境不再交付六层横向背景图。正式交付为模块化 Mesh、材质图集、场景 Prefab、碰撞代理、部署 Decal 和正交镜头预览。

### 6.2 预算

- 单场静态环境常态不高于 15 万三角面。
- 公共建筑套件使用材质图集，单场环境材质种类不高于 12。
- 静态建筑、地面和不可移动装饰优先使用静态批处理。
- 前景遮挡物不得覆盖战线；必须设置透明淡出、隐藏层或限制高度。
- 关卡美术不能改变格位宽度、部署范围、攻击距离和实际碰撞。

## 7. 光照与阴影

- 基础方案为一盏方向光、环境光、烘焙或简化的静态照明。
- 单位使用低成本方向阴影或脚底接触阴影；阴影关闭后仍能辨认站位。
- 不允许依赖 SSAO、Bloom、景深或高曝光表现职业与状态。
- 战斗特效不得把单位轮廓、生命条、部署格或攻击方向连续遮挡超过 0.3 秒。
- Android 降级档允许关闭实时单位阴影、降低粒子数和材质精度，不得删除关键命中反馈。

## 8. 战斗特效

主要特效使用 3D Particle、Mesh Trail、Billboard 和地面 Decal 组合。2D 序列帧只作为粒子纹理，不作为完整技能的唯一交付。

| 类型 | 首选实现 |
|---|---|
| 斩击、穿刺 | Mesh Trail、短时 Billboard |
| 震击、击退 | 地面 Decal、碎片粒子、方向性尘线 |
| 火、水、冰 | 粒子、翻页纹理、简化 Mesh |
| 屏障 | 单层透明 Mesh、受击局部裂纹 |
| 部署与召唤 | 地面 Decal、竖向粒子、短时模型显现 |
| UI 状态 | 2D 图标、屏幕空间提示 |

## 9. UI 与三维战场衔接

- 卡牌、按钮、日志和顶栏使用屏幕空间 UI。
- 单位生命条、状态图标和目标提示使用世界坐标投影到屏幕空间，不直接挂在模型材质上。
- 部署预览使用地面 Decal；合法、选中、非法状态同时通过颜色与形状区分。
- 点击和拖放以战场碰撞平面为判定依据，不使用模型轮廓作为唯一点击区域。
- 屏幕 UI、单位和环境分别设置渲染层，避免生命条被三维模型遮挡。

## 10. 资源组织

```text
assets/
  art-2d/
    cards/
    portraits/
    ui/
    marketing/
  art-3d/
    characters/
    units/
    creatures/
    environments/
    vfx/
    shared/
  bundles/
    common/
    battle-core/
    chapter-01/
    character-showcase/
```

角色、公共材质、战斗核心和章节场景分别设置 Asset Bundle。Web 首屏不加载未进入关卡的角色模型和章节环境；Android 使用同一依赖关系，单独配置贴图压缩和画质档位。

## 12. A0 验收

A0 必须完成 U002 折锋枪兵、U008 霆脊巨兽和 E104 双线交锋的真 3D 验证场景，并满足以下条件：

- 三档相机俯角完成同条件对比，锁定最终俯角和单位投影尺寸。
- U002 与 U008 均以真实模型、骨骼动画和 Prefab 运行，不使用序列帧替代。
- Idle、Move、Attack、Hit、Death 五个动作时序正确，移动不产生脚底漂移。
- 丝袜、薄纱、羽毛和屏障不存在明显透明排序错误。
- 24 个单位同时运行时达到首发性能基线。
- 关闭阴影和后处理后，职业、敌我、朝向、生命和部署区域仍可辨认。
- Chrome、Edge 完成一局战斗，无模型消失、材质丢失、动画断裂和显存持续增长。

未通过 A0 时，不展开二十八兵种批量建模、全章节环境或大批量特效制作。
