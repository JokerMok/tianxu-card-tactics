# 天墟：万象战阵

Cocos Creator 3.8.8 横屏战术卡牌游戏。沿用现有工程、场景身份和仓库；本机 Node.js 权威服务负责账号、战斗、经济、社交与 SQLite 存档。客户端通过同一服务输入和显示，AI 与玩家使用同一个战斗核心。

## 本机启动

环境：Node.js **22.18 或更新**（当前实测 25.9.0）、Python 3、Cocos Creator **3.8.8**。构建脚本在 macOS 使用已安装的 Creator；其他安装位置可设置 `COCOS_CREATOR_BIN`。

```sh
npm start
```

访问 **http://127.0.0.1:7400**，自行注册本地账号并创建角色。端口可用 `TIANXU_PORT=7401 npm start` 调整。一个入口启动前后端和数据服务，退出时按 Ctrl+C。首次缺少资源或客户端时会先导入、构建；已有产物直接启动。更改客户端源码后执行 `npm run build`，随后刷新页面；更改服务端后重启服务。

两个独立客户端可分别打开 `/` 和 `/?client=second`，使用两个独立账号；该参数只隔离浏览器登录槽，不会创建虚假玩家。合作支持 2–4 人；竞技支持 1v1、2v2、4v4；天梯、竞技赛和公会城战为双账号对战。所有参与者必须实际加入、准备并提交操作。

## 资源要求

**仓库不附带完整官方素材，也不是无需资源即可开箱运行的安装包。** 真实图片、声音、动画及配置从用户持有的完整逆向项目本地导入，不联网下载，不连接官方服务。

默认从父目录 `KingsCall-原版客户端逆向研究/` 导入。移动后明确指定完整项目根（`client-handoff/` 的上级）：

```sh
python3 scripts/import-kings-call.py --source '/path/to/KingsCall-原版客户端逆向研究' --resources all
npm run build
npm start
```

也可设置 `KINGS_CALL_SOURCE`。必须有交接索引、配置、动画、资源及其引用的已转换文件；轻量审阅 ZIP 不足。导入只读取原件，保留稳定来源映射和 `main/media` 命名空间。运行版本为 `main`；`media` 不混入数值规则。导入产物位于 `cocos-client/assets/resources/recovered/`，约 986 MB（当前内容），由 Git 忽略。`--resources none` 只更新元数据并复用已有文件，不会新导入缺少的媒体。

## 游玩范围

- 账号、四职业角色、主城、引导、原版剧情和章节地图；主线、单人/合作副本、精英分支、通天塔、世界 Boss、禁地、宠物岛及无蓝方清场挑战。
- 卡牌、卡组、技能、状态、真实多帧角色/技能动画、原版战场与声音；按地图和触发器控制 12 列、1–4 行，合作时扩至容纳队伍所需行数。
- 背包、装备、强化、符文、炼制、融合、点化、商店、职业技能与声望商店、仓库、宠物、坐骑、五类城建、税收、远征、活动、战令、图鉴与称号。
- 好友、世界/私聊/公会聊天、邮件、公会、交易托管、拍卖、多人竞技、天梯周赛、公会领地和三胜/三负竞技赛；本地盟约替代源婚礼任务。

功能、内容覆盖和具体证据分开记录于 [GAME_COMPLETION.md](GAME_COMPLETION.md)。目前导入主库 9,320 张卡牌、8,265 个怪物、728 个技能、68 张战场配置、95 个原始场景、423 个原始节点和 1,129 个原始触发器；另对配置中确实存在但缺少 XML 的 22 个副本做显式本地补建，共 117 个运行场景。并非全部记录都是可加入卡组的有效卡；6,289 张未废弃的有效召唤卡均已校验卡图与可播放模型。创建高级战斗的批量检查不等于新账号逐关打通。

## 存档和迁移

- `backend/data/tianxu.sqlite` 保存账号、角色、完整世界、战斗、经济日志及请求回执；使用 SQLite WAL 与事务，重复请求按账号/角色/请求编号回放，非法或失败操作整体回滚。
- 原网页 campaign 存档键保持原样。新客户端使用 `tianxu.auth.v1` 登录槽；未把旧原型 ID 静默覆盖成 `main` ID。旧原型与新规则隔离读取。
- 数据库 schema 为 1，模块新增字段按访问时补齐。遇到不支持的 schema 拒绝打开并保留原数据库。备份请先停止服务，再复制 SQLite 文件；运行中可使用 SQLite 的在线备份接口，不要只复制主库遗漏 WAL。
- 接管前 Git bundle 和状态快照在父目录 `本地恢复点/tianxu-before-full-20261020-01a15897/`。构建产物 `.local/web` 与缓存可重建，个人存档不可按缓存清理。

## 验证

```sh
npm run verify:content
npm run test:game
npm run verify:campaign
npm run build
npm run verify:visuals
npm run verify
```

`verify` 是现有规则和资源验证入口，不承担本轮视觉复原验收；`verify:legacy` 保留旧原型的历史检查，不代表本轮验收。严格 Cocos 类型检查使用构建生成的引擎声明及 `web-prototype` 的 TypeScript 工具；首次需要先在该目录执行 `npm ci` 并完成一次构建。

报告在 `documentation/recovery/`。HTTP 回归使用临时 SQLite、真实本机连接和独立账号；不修改个人数据库。正常新账号的第一章至第二章验证只使用公开操作、合法战斗和真实升级。时间规则由实际调度执行，定向测试可以传入受控时钟。

## 规则与边界

原版明确的属性、技能类、地图、任务和价格优先恢复。原服务端缺失的 AI、随机奖池、经济、赛季、资源冲突和存档规则由本项目补建，详见 [IMPLEMENTATION_DECISIONS.md](IMPLEMENTATION_DECISIONS.md) 及其分模块依据；不宣称与原服算法逐项相同。

不接官方账号、Steam、真实支付或外部交易。本地补给和战令测试解锁在界面明确标注，均有发放上限与持久化回执。源码存在的缺失敌人、孤立路线、空摆怪配置及源等级 95 与任务 100 的不一致通过显式兼容层处理，原始数据不变。源文件中无后续节点的悬空边不虚构成未取得的章节。

本轮不自动推送。完成定向验证后，须由用户实际游玩确认；旧最终回归报告只保留为历史证据，当前状态以 `.codex/PROJECT_STATE.md` 和本轮修正记录为准。
