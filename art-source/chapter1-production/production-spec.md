# 首章批量角色制作与交付规范

基准：R2卫兵、侍从、枪骑兵；本批食人魔材质修订。风格延续手绘奇幻战术卡牌，不更改玩法。制作清单与原始模型依据在 `documentation/art-samples/chapter1-production/selected.json`，实际尺寸、脚底和注册结果在同目录 `registration.json`。

## 身份与画面

以恢复配置的 modelId 核对装备、种族、原战场位图与卡面，卡名仅辅助查找。Goblin Captain的原战场500像素重甲大轮廓与Bully轻装短曲刃分开，不因共用主题卡面合并。普通人形100–110设计像素，轻小哥布林85，重甲头目120，重骑125；灵体65，翼人125。按站立可见身体高度注册，不能把武器与翅膀的总包围框当身高。

统一固定三分之四视角、左上柔光、哑光笔触、边缘清楚但不套浓黑线。皮肤有冷暖阴影与关节结构，金属保留局部反光，皮革、布、骨与木各有材质。脚下低对比接触阴影，不用大黑圆。不同种族保持体型区别；同模型多实例共享，不把不同装备强行换色合并。实际1200×600战场检查优先于放大图。

## 动作与生成

内置imagegen，参考本项目只读身份与R2图，不上传凭据、数据库；不走本地API/密钥、付费服务或网上下载素材。普通单位的本批默认生成约束（并非所有模型强制规格）：透明背景、6列5行动作、30个有充分间距的独立绘制姿态、固定镜头和装备比例、无文字/UI、同一身体结构；逐模型身份差异见 `selected.json.visualIdentity`。生成记录 `generation.json` 包含输出文件、最终源摘要和参考。

五行依次为警戒待机、实际跨步/四足步态/飞行滑行、蓄势→接触→回收、受击失衡、屈膝倒地/灵体消散。不是整张立绘平移旋转。十个新增对象原提示点恰好均为3/8秒，第4姿态只针对这些对象；旧卫兵/侍从/骑兵等清单实际为3/12秒，不能统一改为3/8。以下只是十对象的制作默认值，帧数、帧时长和循环均由每模型每动作的清单控制：待机8fps循环，地面移动13⅓fps、骑乘16⅔fps，攻击8fps、受击20fps、死亡7.5fps且末帧结束；不改权威命中事件。

两侧使用脚底固定的水平镜像；本视角的装备与朝向已在同场检查，没有独立背面或真实3D方向。飞行与灵体用其自身姿态序列，不套步兵走路。骨堆不是五动作演员；当前沿恢复资源的残留物→重组生命周期播放，见末节。

食人魔只生成材质修改源；技术注册保留原图集逐帧alpha，原轮廓/位置/动作/命中点不变。原始生成稿尺寸漂移不直接进入游戏；`material-registration.json`记录处理。

## 固定注册、打包与质量门槛

1. 源PNG另存 `art-source/chapter1-production/`，原素材只读。走普通30姿态打包工具的输入必须有30个独立主体，遇到相连轮廓或数量不对退回局部排版；不硬按格切开肢体。
2. `batch.json`按稳定modelId、monsterId声明身份、身高、提示点和类型。`produce-batch.py`保持同一缩放、各行动公共脚底、统一裁剪矩形与2像素安全边；绝不逐帧按包围盒重新放锚点。
3. 图集以对象名＋内容SHA命名，WebP无损编码；断言alpha及可见RGB与PNG一致。旧资源的共同透明边裁剪不缩人物，仅同步frame/mount/foot。拒绝超界、空动作或断裂主体。
4. 清单显式ID优先，再按同scope的精确modelId复用，未覆盖回原动画；不按中文名称或模糊词族决定。皮肤回退只换资源，不回退存档。
5. 缓存按图集共享Texture与SpriteFrame，活跃引用不得淘汰，晚到回调检查实例仍存活；最后引用释放。当前明确上限19个图集/128MiB基础RGBA估算，不永久预载全部模型。

重建命令：

```sh
python3 tools/art-samples/prepare-material-retouch.py
python3 tools/art-samples/produce-batch.py --batch art-source/chapter1-production/batch.json
python3 tools/art-samples/package-batch.py --manifest cocos-client/assets/resources/art-samples/v5/manifest.json --output .local/art-production/art-runtime-v5.zip --record art-source/chapter1-production/runtime-package.json --verify-url http://127.0.0.1:7440/art/
```

材质注册脚本固定处理本批两张源稿，无参数；批量工具参数见 `--help`。只有新生成或注册改变时重建，不为复核反复生成。打包仅含运行清单和其直接引用文件，不包含数据库、原反编译目录、源素材与录像。每批记录PNG对照大小、实际下载/压缩包大小、RGBA解码估算、可取得的运行时引用计数，四者不得写成实测显存。

## 定向验收与保留限制

来源身份→独立姿态→固定锚点/事件→真实Cocos同场→正常获得/组牌/部署分别留证。动作夹具只补镜像、密集站位和死亡，不证明普通成长。记录首次未呈现、合法透明、零血歧义与意外空帧，不能一律归为加载。首章随机池和召唤未覆盖仍使用原资源，不过滤玩法。生成姿态可能有细节漂移，当前观察不证明全设备或全量视觉验收；不据此扩大批量上限。

## 机制批次修订：模板例外与预算边界

2026-10-26机制修订固定十九种美术，不新增普通模型。骨堆1169/1187/1380使用恢复的同一47e0模型；鼠群9038使用恢复的8b670模型。骨堆为残留/重组对象，不套步兵动作；鼠群原资源包含群体表现，先以真实Cocos核对，不把放大单鼠当整群。

普通模板的6×5、30姿态和默认fps只控制此工具的普通输入，不是游戏规则。v5已有十九图集不重新生成。每模型 `clips` 已独立声明start/count/fps/loop/cueFrame，允许动作帧数和时长不同，不用全局命中常数；`requiredStatuses`可显式收窄到stand等适用类别（默认仍为普通五态）。未提供的动作返回非原生状态，不编造动画。专用图集通过独立注册清单接入，不强迫通过30主体分割工具；恢复资源沿原显示树/状态时间线播放，发射、命中与结束遵循该资源元数据。

骨堆重组由权威的timed-transform事件触发，客户端同一unitId准备新模型，保留旧完整帧直到新模型可用，再原子切换；重组提示是本版本反馈，不冒称原服特效。发射/命中继续沿现有attack cue/skill-flight队列，不把重组强行当第4攻击帧；这些事件类别不要求共用同一动作。当前sample适配器仍使用stand/walk/atk/hit/die规范名与可选block反应，不声称支持任意事件脚本或任意命名动作。新种类需要明确事件适配后接入，不能只在JSON写字段就算实现。

资源数量需分四层：目录为19种成品（不要求一次加载）；SharedAtlasBank按当前引用持有新图集；引用归零立即释放，没有常驻空闲纹理缓存；预加载仅当前需要的单位，另有有限UI纹理缓存。19图集/128MiB为当前sample包准入预算，**不是单位数、召唤数或服务端合法出牌上限**。全部19张基本解码合计98.32MiB，同模型及死亡/重组交接共享纹理与SpriteFrame。未替换单位、骨堆、鼠群和火龙走恢复资源，其帧树缓存每实例有限，不占sample的19种额度，但仍有自己的CPU/纹理成本，不能把98.32MiB当整页实测显存。

后续新增第20种图集前要基于实际并发引用、解码规格和原资源成本重新做有限准入检查；不能移除活跃纹理、改变合法动作或直接无限提高预算。本轮用19新图集加原资源召唤/死亡短时共存补证，若未触及真实边界，不改缓存系统。下载量/基础RGBA与上批一致；运行引用另留机制批次记录。没有可靠GPU专用内存读数，仍标未测。
