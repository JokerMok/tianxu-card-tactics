## 如何处理本轮问题

| 对象 | 本轮实际修改 | 判断与边界 |
|---|---|---|
| 卫兵轮廓 | 放弃细长简化模型，依据现有卫兵卡面生成绘制姿态；蓝甲、肩甲、盾剑保留，肩/腿更厚，待机盾牌前置，脚底小面积浅接触影。 | 在真实战场约80设计像素的体高下检查，体量接近旧兵，盾剑更易辨认。仍是生成候选，未声称绘制一致性已达批量标准。 |
| 动作 | 独立蓄势、伸剑命中、回收；受伤屈膝后仰；失衡、跪地、侧倒。首轮步态推地不足，单独补绘抬膝/脚跟落地序列，复用播放器。 | 有实际姿态变化，不是单图晃动或整体旋转。左右采用原脚底镜像。伤害/行动顺序/逻辑点未动；攻击命中仍0.25s。 |
| 格挡 | 权威事件`message=blocked`且无扣血时显示“格挡”，用前盾支撑短动作；其他零变化显示“未受伤”；有扣血才后仰，治疗不再受伤。 | 此前发现0伤害仍显示−0并受伤，是表现语义错误，未改服务端规则。旧动画没有格挡姿态时只显示反馈，不伪装成受伤。 |
| 背景 | 林地/遗迹收至上沿及外围，中央连续地面，减弱地平线、草石和强明暗。 | 四排原脚底点和部署热区均未移动，没有靠缩小上排掩盖构图。外围仍保留场景识别。 |
| 卡框 | 数值独立安全底托，种族/职业角标保留；真实Quality0—6各自边色和顶部铆钉数量；选择金线与持有/加入提示独立。详情也用对应品质框。 | 旧183样本漏了Quality6，本轮沿实际配置补核`main:card:23001`，没有把金色压成红色。卡组实际比较0/2/3/6；其余品质有资源/配置核对，未逐张实机穷举。 |
| 底栏/按钮 | 牌库、手牌、墓地图标与短标签，计数移离图标；手牌保持横向。保存/结束回合为主按钮，撤销/筛选/关闭次要；紧凑加减同材质，选中亮框底线、按下凹线、禁用灰化端部斜纹。 | 使用真实非空手牌、选中与拖放检查；可靠热区未变。文字仍动态绘制，原面板与书本继续复用。 |

## 验证结果

- Creator3.8.8原生web-desktop，25个入口源文件与本次构建逐字节匹配；[bundle与源/资源摘要](evidence/release.json)。最终运行包不是复制旧前端。
- 新图集、背景和当前清单全部引用文件经实际HTTP取回逐字节匹配，[记录](evidence/asset-check.json)。同名图集缓存曾导致新布局读旧图片，已改为内容摘要文件名；原件/v1不变。Cocos空场景/609字节脚本包导入失败未当成功，复制运行包前增加明确门禁；最终使用既有有效导入缓存，由Creator重新编译当前源码。
- 单位在位移中能看到抬脚/落脚，攻击蓄势、接触与回收可分辨；实机没有观察到新图集单位周期性整人消失。死亡先完整倒地，再沿现有队列淡出释放；名称位置只读固定规格，未追随逐帧包围盒。判断依据为录像，不以帧数证明质量。
- 专用隔离角色持有26张真实配置卡作展示，不证明普通玩法可获得高阶品质。卡组真实保存为`3/4/23001/1`，服务端确认，关闭重开一致。正常卡组容量、职业和持有校验仍由既有服务执行。库滚动、详情滚动、跨栏移除/加入、草稿和保存均实际操作。[品质夹具依据](evidence/quality-fixture.json)。
- 1280×720视口，画布CSS1280×720、帧缓冲2560×1440（DPR2）；设计1200×600战场内容显示1280×640、比例1.0667，上下40px。复用上轮1200×600/1440×900的结构验证，本轮没有声称重新跑过双尺寸矩阵。
- 本机M5 Pro/48GiB、Node25.9、内置Chromium。单次卡组打开：mousedown到窗口树反馈2.1ms，纹理/解锁就绪152.1ms；rAF P95约10ms（本机缓存已预热的代理指标，不是点击到光子的延迟或全设备结论）。实际截图/滚动/拖放可操作。此前146.1ms同口径，仅作参考，不构成统计性能比较。
- 最终战场6个新卫兵共享1图集，[实机指标](evidence/runtime-final.json)；图集解码基础RGBA9MiB，v1约14MiB。当前清单去重引用约1.37MiB，不含母图与保留迭代中间文件。ArtSkin缓存上限40键、单位图集4条，卡库池56纹理；未做长时显存压力测试。
- 仅执行受影响的图集时钟/命中/取消/格挡/共享/释放检查与既有表现队列回归；mock只证明对应逻辑，不作为美术验收。
