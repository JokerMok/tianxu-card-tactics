## 确认的根因与依据

- 固定敌方英雄的Attack=0来自原monster配置，原件未改；当前英雄也不走普通部队的主动行动循环。不能据此把英雄不主动进攻说成漏执行，未给英雄凭空加攻击。
- `BattleKernel.draw/beginTurn`每个角色自己的非开局回合抽牌，额外抽牌效果也走同一路径；未见轮询重复扣疲劳。原先空抽即累计1、2、3……伤害；敌方兼容牌组仅4／5／7张，起手最多5张，普通步兵尚未走过12列战场，英雄就已被疲劳击杀。这条疲劳算法是本项目兼容规则，见 `IMPLEMENTATION_DECISIONS.md`，不是已恢复的原服公式。
- `content.enemyDeck`原来从同章共享候选池有放回抽牌，没有读取原服deckid牌表。原场景有deckid引用，但现有主配置无对应牌组表；资料 `client-handoff/docs/PVE完整流程与恢复顺序.md` 与交接缺口明确服务端权威算法未取得。关卡固定英雄形象不同，不代表部队具有不同主题。
- `moveUnit`把AIType=1解释为超出“射程+1”就不移动；实际同时影响侍从、弓手和法师，造成远距离永久停步。原客户端没有提供支持这种服务器解释的算法，按本版本修订，而非声称恢复了原服AI。
- `chooseAIAction`同分时固定最小行列，容易堆同一路；基本托管仍取首合法操作。准备等待、合法目标不足和这类站位会产生空行动，未发现网络导致敌方永远不结束回合。
