# 战役附加奖励恢复说明

## 已采用的来源

- 普通战役触发器直接使用 `reputationtype`、`reputationvalue`、`reputationminlevel`、`reputationmaxlevel` 与 `randomgroupprize`。
- 精英遭遇只在战斗记录明确保存 `level.elite: true` 时叠加触发器子节点 `elite` 的固定奖励、声望和随机组奖励。
- 副本目录来自 `scene/fubens.xml`。简单、普通、困难场景 ID 分别对应同一行的奖励预览 ID。
- `scene/fubenprizepreview.xml` 是横向宽表：列组编号就是预览 ID，每一数据行是该预览的一项候选奖励。副本最终战斗节点胜利时，从过滤后的候选项中等概率发一项。场景 2501、2502、2503 分别映射预览 31、35、36。

## 恢复边界

原服务端 `OnlinePrizeTable.xml` 未恢复，因此无法声称复原原服随机组内容或概率。当前实现把 `randomgroupprize` 当作一次真实掉落触发，使用有效主卡、材料和副本门票构造本地奖池，并明确在返回结果中标记 `reconstructed: true`。卡片必须是未废弃、`Type=1`、`MonsterID>0` 且能在怪物表中解析；物品必须能在药剂、凭证或装备表中解析。无效源条目先过滤，不参与抽取。

副本预览只用于真实副本场景的最终节点，不把预览目录解释成原服概率表。预览类型 1/2/3/4/5/6 分别落到银币、金币、卡片、物品、塔币、活动点。

## 结算约束

- 只有战斗记录显示蓝方胜利且调用方传入 `eligible: true` 才发放。
- `record.campaignExtraActors` 按角色记录已处理状态。同一战斗重复调用不会重复发奖；结算时不符合个人进度的角色也会记为已处理，之后不能把进度变化转换为历史战斗的补领资格。
- 声望最小/最大等级按结算时角色等级判断；最大等级为 0 视为不设上限。
- 每次资产变化写入角色经济日志。模块不修改关卡进度，也不创建未来领取资格。
