## 修复与原始依据

- **同节点的一次性奖励不可达。** `content.mjs:level`原来用clearedNodes直接切换到repeat=1；第三章每节点有两条repeat=0，第二条奖励因此被普通入口跳过。现在优先未完成的一次性trigger，全部完成后才选重复挑战。奖励仍取各自原配置，不自动补发；明确请求已完成trigger继续拒绝。本版本采用顺序接续，原服如何选择两条配置未获运行证据，不冒充完整恢复原服路由。
- **地图打勾但章节任务未完成。** 原任务103明确检查308002，而非308001。`pve-systems.mjs:taskView`只补目标triggerId展示字段；`player-ui.mjs`在目标节点已过且仍有一次性配置时显示“森林入口：继续剩余首通挑战”。完成308002后自然变为1/1并可领取，没放宽任务条件。
- **中文。** 当前201正式弹窗已中文，原英文录像早于上轮修复；本轮实机截图见 [201当前版本](evidence/201-current-chinese.png)。八段第三章剧情复用现有原文匹配保护，补十个固定敌方名称。保持艾蕾莱、萨里亚、半精灵等既有词族，原ID、英文原文与配置不变；新增均为候选译文，非官方中文恢复。
- **败因反馈。** 疲劳扣血原来仅飘普通负数，战报写“战斗事件”。现按同一HP事件显示“疲劳−N”，战报区分疲劳及牌库耗尽，没有改变伤害、队列或死亡生命周期。见 [真实连续帧中的疲劳反馈](evidence/fatigue-feedback-frame.png)。
- **客户端收尾待最终构建核验。** 实机战报35条短行被通用SHRINK缩小，源码已改按12行／每行最多30字分页，保留13设计字号、16行高与原翻页控件。另捕获准备中手牌图像异步返回后向已释放节点addComponent的错误，在drawSmallCard的await后核验父／图片节点与disposed。两项还需重构建后实机核验，不能算当前正式入口已通过。

## 前两章实际体验结论

复用原隔离库16场第一章、8场第二章记录，没有重新刷完整章节。见 [原战斗分析](evidence/previous-chapters-experience.json)、[当前遭遇边界](evidence/encounter-boundaries.json)。

1. 第二章固定英雄不同，生命9—12、攻击均0；八关部队实际抽取不同，但同用217卡兼容池、每英雄5张牌。第一章五个固定英雄同用129卡池、4张牌。原配置deckid不同，当前服务没有按原服deckid恢复专属牌组；遭遇差异有随机表象，主题和战术区分仍弱。本轮未改池子、概率或敌方强度。
2. 第二章八场敌方最后一击全部来自疲劳，英雄总有效伤害82点疲劳、3点其他来源；202—207未造成非疲劳英雄伤害。单位仍会接战、击杀与施加状态，但不能据此说每关都要求不同策略。203手动技能有真实命中，未证明其是获胜必要条件。
3. 同八个历史entryState、相同牌组／种子，离线比较首合法托管与一个前沿分路启发式：七场胜负与结束计数相同，208前沿方案反而从8变10；不是最优手动策略、胜率或真实玩家对照。见 [部署对照](evidence/strategy-counterfactual.json)。对失败302的同种子有限对照，七卡仍败14，实际保存11卡组胜15、首次己方疲劳6→14；这与实机重试一致，但改牌也会影响洗牌顺序，不外推普遍胜率。见 [构筑对照](evidence/deck-counterfactual.json)。
4. 第二章敌方每场有1—2段未出现出牌／移动／攻击／效果的行动，部分单位整个遭遇没有移动或攻击。准备等待、射程及兼容AIType=1的远距离保守移动门槛可解释这些记录，未见网络卡住后敌方永远不结束行动。高级AI优化仍暂缓；没有批量改AI。
5. 第二章202／204／206／207的首次成功指令至结算约13.1／23.8／18.4／24.3秒，含客户端动画等待；203含人工策略停留约95.7秒，205含刷新／重启约110.7秒，不能算纯战斗性能。日志无法单独分离每次思考与动画耗时。7→10即使领取现有任务还需28次重复胜利，机械刷关是已确认的成长体验限制；本轮不擅自重平衡经验表。
