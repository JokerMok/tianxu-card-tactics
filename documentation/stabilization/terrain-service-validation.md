# 地形牌权威服务定向验证

核对日期：2026-10-23。范围仅为本机隔离数据库上的真实 HTTP、SQLite 持久化和服务进程重启；不代表浏览器界面、公网、生产或完整游戏回归验收。

## 自动验证

命令：

```sh
node --test --test-concurrency=1 backend/game/terrain-integration.test.mjs
```

结果：2 个用例通过，0 失败，约 12.8 秒。

覆盖的真实服务链路：

- 经 `/api/register`、`character.create` 建立两个隔离账号和角色；测试数据只写入系统临时目录中的独立 SQLite。
- 经 `deck.save` 拒绝同名地形牌 4 张的非法卡组，随后保存含 `50806`、`50807` 各 3 张及 4 张真实生物牌的 10 张合法卡组。
- 经配置中的可进入 PVE 节点执行 `pve.start`，从服务返回的 `legalPlays` 选择真实地形落点，再经 `battle.command` 施放。
- 越界落点被拒绝，手牌、墓地、RNG、事件和战斗修订均不变化。
- 相同 `requestId` 和相同载荷重试返回持久回执，不再扣牌、不新增地形/触发、不推进 RNG 或修订；相同编号不同载荷被既有请求指纹机制拒绝。
- 两页面使用同一旧 `expectedActorRevision` 时，后一个命令返回 `ACTOR_CONFLICT`；另一账号携带目标角色 ID 操作返回 401，权威战斗不变化。
- 重新登录、关闭服务后打开同一数据库，均保留地形快照、`remainingTurns=1`、RNG、卡牌区域数量和事件数。
- 活动战斗经原子备份恢复到另一数据库后仍保留相同地形及持续时间；在恢复库继续战斗，孵化地形于施放者回合结束时触发并移除。
- 恢复库中的战斗继续至 PVE 胜利；`settlements` 中该角色仅有一条业务结算。随后回放早期地形请求只返回历史回执，不恢复旧战斗、不重复触发，也不重复发奖。
- 将版本 1 活动战斗的可选 `terrains` 字段删除并重启后，状态仍可读取，后续 `battle.command` 仍可执行。

## 私有浏览器验收夹具

`.local/terrain-acceptance/` 是 Git 忽略的本机夹具：

- `prepare.mjs` 只创建独立 `game.sqlite`，通过真实 HTTP 保存同一套合法 10 张卡组并开启正式 PVE。
- `identity.json` 保存本机试玩凭据，权限为 `0600`；验证输出不打印账号或密码。
- `start.command` 仅绑定 `127.0.0.1:7425`。当前夹具已核对正式登录和 `/api/state` 均为 HTTP 200，活动战斗开局手牌存在 `50806`/`50807` 且服务返回合法地形落点。
- 第一账号保留上述孵化地形活动战斗，并补齐到 4 个角色用于正式选角页切换核对；其他角色没有改动首角色战斗。
- `secondary` 账号保存 `50808`、`50809`、`50903` 各 3 张与 1 张真实生物牌的合法 10 张卡组，并已开启独立正式 PVE；开局可施放永久地形，用于刷新、断线和服务重启后的留存核对。

该夹具用于从现有正式登录页进行浏览器操作，不是另一套预览页面。此文档不把服务接口核对写成浏览器 UI 已验收；浏览器中的地形可视化、点击命中、战报呈现和刷新后的画面仍需由实际浏览器操作单独记录。
