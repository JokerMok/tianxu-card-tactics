# 隐私合规实施契约

版本：`privacy-v1`
适用范围：客户端隐私服务、数据主体权利处理、发行审核材料

本文件记录客户端实现必须满足的控制项。实际运营主体、平台条款、适用法域及最终隐私政策以发行方审核版本为准；本文件不替代法律意见。

## 数据处理与同意

- 必要运行处理与可选处理分离。分析、个性化和营销三类可选目的默认关闭。
- 可选处理必须对应当前政策版本、明确目的、明确来源和可追溯请求号；撤回同意写入 `granted: false`。
- 未完成年龄状态确认时，所有可选处理均不得执行。已验证未成年人仅允许分析目的，且必须存在监护人验证；营销和个性化始终关闭。
- 同意记录不得通过审计日志输出原始主体标识或个人字段。

## 年龄分级与权限

- 年龄状态只允许经配置运营凭据写入；客户端不能用主体自报结果绕过验证。
- 主体凭据只能访问自身数据。运营接口必须使用初始化时配置的独立凭据；缺少凭据、凭据不匹配或存储接口不完整时服务拒绝执行。
- 审计日志只允许授权运营方读取，主体不能枚举其他主体、账本或全局审计记录。

## 数据主体权利

服务提供以下确定性操作：

| 权利 | 接口 | 控制 |
| --- | --- | --- |
| 访问 | `accessData` | 返回主体当前数据及保留截止时间 |
| 可携带导出 | `exportData` | 返回确定性 `application/json` 文档 |
| 更正 | `correctData` | 以完整、经过校验的数据快照原子替换 |
| 删除 | `deleteData` | 删除主体数据、同意、年龄状态及含个人数据的回放账本 |

所有写入或权利请求都要求非空 `requestId`。同一请求号只能绑定一个操作、主体和载荷；相同请求重放原结果，载荷冲突或跨操作复用直接拒绝。访问和导出重放前必须重新通过主体匹配、权限和保留期限校验；数据已过期或不可读时不得返回原回放结果。删除后的合法删除请求仍可重放；删除前的访问、导出和更正结果不会在删除后继续保留。

访问和导出可以返回主体本人提交的敏感个人字段，这是数据主体权利的必要结果。服务禁止把密码、令牌、密钥、授权头、Cookie、CVV 等凭据字段写入主体数据；审计记录不保存任何原始数据值，只保存主体指纹、操作、请求号、结果、时间和敏感字段数量。

## 保留期限与审计

- 每个主体数据记录必须同时包含 `updatedAt` 与 `retentionUntil`；到期数据不得继续访问或导出。
- 授权运营方执行 `purgeExpired` 后，已到期主体数据、同意和年龄状态一并清理。清理失败不产生成功结果。
- 审计记录按配置保留期限清理；审计中的主体标识为不记录原始主体 ID 的确定性指纹，不包含原始数据内容或凭据。该指纹不是密码学匿名化结果，不得替代正式脱敏方案。
- 存储适配器的读取、替换、删除和到期清理必须是原子操作；读取结果的 `subjectId` 必须与请求主体一致。删除和到期清理完成后必须再次读取确认数据不可读；底层空操作、异常或残留均按失败关闭处理。
- 业务状态写入前必须完成审计时钟和审计持久化准备；任一审计失败不得留下业务写入、成功请求账本或接受状态的审计记录。`purgeExpired` 的请求指纹只包含稳定请求语义，不包含动态执行时间。

## 发布审核要求

发行前必须确认：隐私政策、平台隐私声明、年龄分级、同意界面、账号注销入口、数据删除入口和数据处理方信息与本契约版本一致。若具体平台或法域要求更严格，以更严格要求为准。
