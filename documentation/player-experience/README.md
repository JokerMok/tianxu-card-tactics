## 确认的瓶颈及修改

1. `backend/game/growth-systems.mjs:dataRows` 在每次状态展示反复遍历只读配置。冷调用 CPU profile 指向此处；增加按源数组引用的 WeakMap 过滤结果缓存，不缓存玩家数据。源表替换或长度变化会重建，配置只读是其边界。同一冻结普通角色快照三次比较，输出完全一致；中位数从 369.2ms 降至 22.6ms，见 [growth-comparison.json](evidence/growth-comparison.json)。
2. `OriginalUi.mount` 原来沿节点串行等待图片。现在仅收集当前组件的图片依赖、去重后最多六路准备；共用现有纹理请求缓存，节点、层级与控制器仍按原顺序建立。父节点失效后停止继续调度，不预载全游戏。主城仍创建 301 个节点，准备耗时 572.8→121.4ms；节点创建本身约 2.2→1.5ms，并非主要瓶颈。

## 检查边界与剩余项

当前正式和归档入口均由真实 Creator 构建，源码摘要相符；正式入口严格 TypeScript 检查、组件图片准备定向检查、原逐帧动画检查、运行包边界检查及精简范围检查通过。配置成长测试 23 项中有一项历史失败：通用消耗品测试要求使用已批准暂缓的食物，实际返回 `STAGE_PAUSED`；用改动前模块重现同一失败，本轮未恢复该玩法或宣称全绿。没有全项目回归。
