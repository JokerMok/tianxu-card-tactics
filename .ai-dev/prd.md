# 横屏战术卡牌原型开发需求基线

版本：v2.1  
日期：2026-08-18  
依据：`项目现状与模块化开发计划-v2.0.md`

## 产品目标

完成可在 PC Web 与 Android 横屏运行的单人战术卡牌游戏：玩家从主城进入战斗，使用配置化的卡牌、单位、职业与关卡完成 PVE，并在主线、副本、养成、内容和发行能力中形成可验证闭环。

## 本轮范围

1. 修复并复验既有配置加载链，恢复 M1 阶段完整质量门。
2. 完成 M3 战斗 Harness v2 与正式资产性能门，关闭“可玩闭环”证据缺口。
3. 按原始路线图推进 M4 至 M8：首章、PVE、养成、UI 与美术、内容工具、平台、账号、运营与发行。
4. React 原型仅作为规则对照，不新增产品 UI 或正式玩法。

## 非范围

1. 不新增原路线图外的玩法、商业系统、平台或内容模块。
2. 不将修复轮次、审查意见或执行器问题登记为产品功能。
3. 不修改 `cocos-client/library`、`temp`、`build` 与依赖目录。

## 需求

| ID | 需求 | 验收结果 |
|---|---|---|
| REQ-001 | 配置、存档、时间与奖励服务必须版本化、可校验、可回滚。 | 配置加载、跨表、存档、时间与奖励验证全部通过。 |
| REQ-002 | Cocos 战斗核心必须与 React 对照规则保持确定性一致。 | Golden Runner、独立 Battle Runner、跨端对拍与中立平衡全部通过。 |
| REQ-003 | 玩家必须可从主城进入真实 Cocos 战斗并正常返回。 | Harness 可驱动完整输入链；不得使用测试扣血入口替代战斗。 |
| REQ-004 | 战斗表现不得改写核心状态，且战斗结果必须幂等提交。 | 表现、控制、退出、结算与状态哈希回归通过。 |
| REQ-005 | 第一章十二关、收藏、牌组、成长与任务必须形成主线闭环。 | 可完成连续三十分钟游玩，无资源负数、重复奖励或存档损坏。 |
| REQ-006 | 副本、塔、Boss 与援军必须与主线奖励、进度隔离。 | PVE 奖励隔离回归通过。 |
| REQ-007 | 养成、经济、声望与商店必须可审计且无经济死锁。 | 三十日经济模拟通过。 |
| REQ-008 | UI、美术、资源与性能必须满足横屏可操作和正式资产门槛。 | 24 单位、六层场景、基础特效下 PC Web 达到 55 FPS、P95 不高于 22 ms。 |
| REQ-009 | 内容、平台、账号、运营、支付与合规必须具备发布前验证。 | 发布前稳定性、性能、安全与恢复演练通过。 |

## 质量原则

1. 数据、规则、表现和元游戏事务分层；规则变更顺序固定为文档、测试、核心、表现。
2. 每项工作必须有自动化验收；不得删测、降断言、放宽阈值或写死结果。
3. 每次执行只处理一个任务包；跨模块问题登记后回到对应源模块处理。
4. 任务通过独立审查后，由协调器更新状态台账；历史尝试仅保留在归档，不进入产品主图。
