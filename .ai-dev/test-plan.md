## 执行规定

1. 每个任务在改动前运行本任务基线；基线失败则停止修改并回报。
2. 正例、非法输入、重复调用、恢复路径至少各覆盖一项；涉及资产或性能时必须包含缺资源或不合格资产的反例。
3. 任务验证命令必须是已存在的脚本，或该任务允许范围内创建的直接 Node 验证器；直接验证器必须读取真实目标，具备正反例，禁止仅输出固定 PASS。
4. 截图、浏览器和构建产物只能作为已声明的受控基线输入；验证器不得向任务允许范围外写入文件。
5. Web 构建使用锁文件安装的受控依赖；不得以“命令不存在”代替验证结果。
6. 通过标准为所有必跑命令退出码为零、范围检查通过、独立审查无 P0/P1/P2。
